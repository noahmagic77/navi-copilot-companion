# NAVI v0.6.2 — Reliable editor-anchor flight (Preview)

Fix the diagnosed loss of the diagnostic marker while NAVI approaches it. Desktop capture included NAVI's own layered window, so the fairy covered the two-colour beacon and the detector correctly rejected the obscured shape.

## Fixed

- Temporarily exclude only NAVI's native fairy and speech windows from Windows capture during an explicit anchor request. Restore their capture policy on stop, expiry or focus loss. Keep desktop composition for Chromium's GPU-rendered editor surface; owner-DC-only capture was tested and rejected because it did not capture that surface reliably.
- Synchronize GDI bitmap writes before reading/clearing pixels. Preserve the four-scans-per-second, 20-second and RAM-only limits; no OCR or saved/transmitted screen images.
- Report distinct unavailable stages: capture failure, missing/ambiguous marker, unavailable self-exclusion, insufficient space and timeout. Show a concise explanation in the diagnostic hover.
- Recheck foreground ownership before reading pixels; preserve mouse priority and cancellation on edits, focus loss, pause, preview, games and direct actions.
- Require successful native Windows acceptance for the exact main commit before publishing a GitHub preview, in addition to the existing CI/package checks.

## Validation

- A real Windows regression fixture first proves an opaque layered window hides the marker, then verifies that excluding NAVI's own windows restores detection without hiding the on-screen overlay. Capture policy restoration is checked for both fairy and speech windows.
- The previously failing hosted **Native Windows Overlay** workflow now passes, including actual measured arrival, window tracking, speech click-through, rendering and IPC.
- Complete isolated VS Code → rendered beacon → native arrival passes for baseline, zoom and duplicate-document split editors with wrapped text. Scrolling reacquires the changed physical line height; removing the diagnosis stops tracking. This is actual native arrival, beyond the earlier renderer-only checks.
- 84 JavaScript/TypeScript tests and native Go tests pass. The existing 110-animation browser audit remains part of CI; native tests still render all 110 previews.

## Availability and limits

Precise flight requires Windows capture-exclusion support (Windows 10 version 2004+). While tracking, NAVI's native windows may be absent from screen recordings/captures for at most 20 seconds; they remain visible on screen and their normal capture policy is restored afterward. Unsupported capture or missing/ambiguous markers keep the ordinary editor marker instead of guessing a location. Disable `navi.overlay.editorAnchors` to use marker-only navigation.

The native fairy keeps the measured target height with its existing 60-DIP left offset. Different physical monitors, HDR/forced contrast modes and human acceptance in your normal profile remain separate from the automated coverage; no universal display guarantee is claimed.

Install the attached `navi-copilot-companion-0.6.2.vsix` via **Extensions → … → Install from VSIX…**, then reload VS Code. The release includes its SHA-256 and a sanitized anchor-audit JSON.
